# Отчет по лабораторной работе №4 (n8n)

## Краткое описание выполненного
В ходе выполнения лабораторной работы была освоена low-code платформа автоматизации n8n. 
n8n был успешно установлен и запущен локально через Docker (с подключением двух volume: для данных n8n и для папки /data). 
Были изучены базовые и продвинутые ноды (Manual Trigger, Set/Edit Fields, Code, IF, HTTP Request, Schedule Trigger), а также настроена интеграция с Redis (создание, чтение, удаление и проверка ключа). 
В качестве индивидуальной ачивки (Ачивка 9) была реализована интеграция с уникальным внешним сервисом — GitHub (получение списка репозиториев пользователя).

## Использованные AI-промпты
В процессе работы использовались следующие ключевые промпты (через ИИ-ассистента):
1. «Помоги запустить n8n в Docker с двумя volume для лабораторной работы». 
   *Результат: была подобрана корректная команда `docker run` с флагами `-v` и переменными окружения.*
2. «Как настроить Redis Credentials в n8n, если n8n в контейнере, а Redis тоже в контейнере?» 
   *Результат: выяснили, что нужно использовать хост `host.docker.internal`, а не `localhost`.*
3. «Напиши базовый JavaScript-код для узла Code (с let, const, if/else, for), который возвращает объект с полем payload».
   *Результат: код был успешно применен в flow-02 и flow-03.*
4. «Почему в узле GitHub при выборе 'Get a user's repositories' ошибка 'Parameter Repository Owner is required'?»
   *Результат: выяснили, что нужно указать логин владельца в обязательном поле.*

## Освоенные ноды
В ходе работы были освоены и применены следующие ноды:
- **Manual Trigger** — для ручного запуска workflow.
- **Edit Fields (Set)** — для создания новых полей (payload, topic, timestamp) и работы с выражениями (`{{ $now }}`).
- **Code** — для выполнения JavaScript-кода (циклы, массивы, объекты, обработка JSON).
- **IF** — для ветвления логики (разделение на true/false по условию).
- **HTTP Request** — для GET-запроса к публичному API (catfacts).
- **Schedule Trigger** — для запуска workflow по расписанию (каждую минуту).
- **Redis** — для операций Set, Get, Delete и Exists с базой данных.
- **GitHub** — для интеграции с внешним сервисом и получения данных репозиториев.

## Выводы
В результате выполнения работы я научилась работать с платформой n8n. Поняла, как устроены workflow, как передаются данные между узлами (в виде JSON-объектов). 
Особенно полезным было разобраться с подключением внешних сервисов через Credentials (Redis и GitHub) и понять, как контейнеры общаются друг с другом внутри Docker (на примере `host.docker.internal`). 
n8n показал себя как мощный инструмент для автоматизации, который позволяет быстро собирать интеграции без написания большого количества кода.
